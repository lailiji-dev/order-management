# 前端优化基准

在 `peiliao` 目录运行：

```powershell
node update-v3/tests/optimization-benchmark.mjs
```

脚本比较保留的 `update-v2` 和当前 `update-v3`，每项默认运行三次，取中位数。通过 `BENCH_ITERATIONS` 可调整次数，也可在命令后指定单一版本目录。结果写入同目录 `optimization-benchmark-results.json`。

三个数据场景为 100 笔同日订单、1000 笔同日订单、10000 笔分布在 30 天的订单。每笔订单使用相同的产品明细结构，同时包含已取、未取和早取星标。

观察的指标包括初始 DOM 初始化、重复无变化渲染、月历渲染、重复无变化轮询、初始订单卡片和 DOM 节点数、重复渲染是否保留卡片节点，以及完整静态资源大小。无变化轮询先通过一次完整响应建立 ETag，再计算连续三次轮询的客户端处理时间和接口响应体大小。

该测试只使用临时 jsdom、合成数据和本地资源。它不会访问生产接口，不会登录员工账号，不会创建真实订单，也不会控制用户浏览器。静态资源请求由本地拦截器处理，所有 API 请求均为模拟响应。

结果代表相同机器上的应用计算及 DOM 开销，不能替代真实浏览器的页面绘制或外网延迟。接口字节数是未压缩响应体，初始资源字节数未包含生产环境 gzip 的收益。
