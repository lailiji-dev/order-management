# 前端安全评估与修复

评估对象为 `update-v3/site`，修复源为 `update-v4/site`。本报告不代表服务器入侵取证或对生产数据进行过读取；全部攻击复现和订单测试采用本机隔离数据。

| 发现 | 证据与范围 | 修复 |
| --- | --- | --- |
| 退出后敏感数据残留 | `sharedHide` 仅隐藏页面，客户姓名、电话、备注、订单仍在 DOM、全局 state 和完整 localStorage 缓存中；后台也只隐藏表格 | 退出或会话失效清空订单、配方、打印、详情和后台表格的 DOM、内存引用、数据索引、密码草稿；共享整库不再写入 localStorage，只保存本机计算计划 |
| 旧版/本机备份日期触发 DOM XSS | `buildPrintHTML` 将 `calcDateText()` 直接拼进 HTML；隔离测试从旧本机缓存加载带 `img onerror` 的日期，可执行内联处理器 | 转义打印日期、订单/生产日期、数量属性；后台 id 和 quantity 同样统一转义。当前共享 API 对订单日期、数量有规范化，尚未证实匿名远程持久型利用 |
| 旧会话迟到请求可回填界面 | 同步成功回调、后台刷新和初始 `auth/me` 没有完整的会话/登录代际约束 | 保存、激活、导入、后台刷新和登录结果绑定发起时的会话；账户切换或退出后丢弃旧回调，不允许重新填入旧账号数据或把新账号退出 |
| 浏览器历史缓存恢复旧页面 | 返回/前进缓存可以恢复已渲染页面，原实现等轮询才发现服务器注销 | `pageshow.persisted` 先清私有数据，再验证当前 Cookie；验证成功后恢复授权界面 |
| 缺少针对新密码策略的界面约束 | 密码修改、创建员工和重置界面仍提示 7 位 | 同步新后端的 15～200 位输入限制与长短语提示，最终强度检查由服务器实施，旧账号登录不被前端长度限制 |

未发现前端使用 `eval`、动态函数构造、跨站接口发送、远端 CDN 脚本或 `javascript:` URL。导出为 JSON，不执行导入文件。类别、产品、原料、客户、备注、订单号和审计字段均按文本转义；仍应依靠 API 权限、字段校验及浏览器策略共同防护。

## 保留的数据与边界

成功同步的整库缓存在 v4 第一次加载时提取本机计算计划后删除，损坏的旧缓存也会删除。服务端数据不会因这一步丢失。尚未合并的原设备 `peiliao_data_v1`、原始迁移备份、导入备份、冲突备份和按用户保存的未同步修改继续保留，以免丢失原订单。

这些旧备份/未同步队列仍是本机浏览器中的明文业务数据，具有该浏览器配置访问权限的人能够读取；本次不虚构“已加密”或“全部本地数据均已清除”。此限制不提供远程未授权 API 访问能力。安全清理这些数据应在确认历史订单完整合并、未同步修改已保存之后进行，不应凭修复脚本直接删除唯一原件。

未采用由当前 CSRF 派生密钥加密离线队列：退出、重置密码、过期或更换会话会更换 CSRF，易使已保存的未同步订单无法恢复。保留可恢复性比未经验证地引入密钥流程稳妥。

## CSP 配置建议

当前正式 HTML 的 JavaScript 均为同站外部文件，事件监听均使用 `addEventListener`，没有内联脚本或内联事件，因此可以直接部署：

```nginx
add_header Content-Security-Policy "default-src 'none'; script-src 'self'; script-src-attr 'none'; style-src 'self' 'unsafe-inline'; connect-src 'self'; img-src 'self'; font-src 'self'; object-src 'none'; base-uri 'none'; frame-ancestors 'none'; form-action 'self'; upgrade-insecure-requests" always;
add_header X-Frame-Options "DENY" always;
add_header Referrer-Policy "no-referrer" always;
add_header X-Content-Type-Options "nosniff" always;
```

`style-src` 暂时允许内联样式，因为日期按钮和若干容器仍有固定的 `style` 属性；不存在可控数据进入样式值。无需启用 `unsafe-inline` 脚本或 `unsafe-eval`。Nginx 某个 location 一旦声明自己的 `add_header`，需在该 location 中确保包含上述头，不能只依赖 server 级继承。保持现有 HTTPS/HSTS、HTML/API no-store 与哈希资源 immutable 缓存。

策略含义参考 [MDN script-src](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/script-src)、[MDN frame-ancestors](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/frame-ancestors)。部署后需要在真实浏览器确认手机、订单、配方、打印和 JSON 导出没有策略拦截。

## 验证结果

- `frontend-security-test.mjs`：23 项安全检查通过，含旧版本 XSS 复现、升级缓存清理、退出清 DOM/内存、历史缓存恢复、跨账号迟到 200/401 请求、后台退出与登录竞争、密码输入规则。
- `security-compat-frontend-ui-test.mjs`：15 项原业务界面回归通过。
- `security-compat-frontend-protocol-test.mjs`：10 项同步协议回归通过。
- `security-compat-optimization-review-test.mjs`：11 项分页、性能和离线恢复回归通过。
- `security-connected-test.mjs`：实际 v4 API + 临时数据库集成通过，包括原设备迁移、并发新增编号、员工归属、冲突备份、过期会话和断网重载恢复。

前端共 59 项断言检查，另有 1 组完整前后端隔离集成流程；未创建生产测试订单或生产员工。
